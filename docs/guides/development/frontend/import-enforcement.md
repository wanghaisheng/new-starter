## 2. 工具与配置

为了确保规范被强制执行，我们添加了以下工具和配置：

1. **ESLint 配置**：
   - 创建了 `.eslintrc.js` 文件，添加了 `no-relative-import-paths` 规则
   - 配置了 `import/order` 规则，定义了导入顺序规范

2. **开发依赖**：
   - 添加了 `eslint-plugin-no-relative-import-paths` 插件
   - 添加了 `eslint-plugin-import` 插件，用于管理导入顺序

3. **自动检查脚本**：
   - 创建了 `tools/check-import-paths.js` 脚本，用于扫描和报告相对导入路径
   - 该脚本支持自动修复模式，可将相对导入转换为绝对导入

4. **npm 脚本**：
   - 添加了 `npm run lint:imports` 命令，检查代码库中的相对导入路径
   - 添加了 `npm run lint:imports:fix` 命令，尝试自动修复相对导入路径

## 3. 实施流程

为了确保顺利过渡到新的导入路径规范，我们建议按照以下流程实施：

1. **团队宣导**：
   - 在团队会议中介绍新的导入路径规范及其优势
   - 分享导入路径规范文档 (`docs/guides/import-path-standards.md`)
   - 演示如何使用检查工具和自动修复功能

2. **分批迁移**：
   - 先修复核心模块和共享组件中的相对导入
   - 然后分批修复其他模块中的相对导入
   - 每批次修复后进行全面测试，确保功能正常

3. **代码审查**：
   - 将导入路径规范作为代码审查的一项重要检查点
   - 使用 `npm run lint:imports` 命令验证提交的代码是否符合规范
   - 拒绝合并含有相对导入路径的代码

4. **CI/CD 集成**：
   - 在 CI/CD 流程中添加导入路径检查步骤
   - 对于不符合规范的代码，CI 构建失败，强制开发者修复问题

## 4. 验证与监控

为了确保规范得到有效实施，我们建议采取以下验证和监控措施：

1. **定期审查**：
   - 每周运行一次 `npm run lint:imports` 检查整个代码库
   - 监控相对导入路径的数量，确保其随时间减少

2. **自动化检查**：
   - 在预提交钩子中添加导入路径检查
   - 在持续集成流程中运行导入路径检查

3. **反馈机制**：
   - 建立渠道，收集开发者对导入路径规范的反馈
   - 根据反馈优化规范和工具

## 5. 常见问题

**问：如何处理样式文件导入？**  
答：样式文件（.css、.scss等）可以继续使用相对路径导入，这是规范中明确的例外情况。

**问：项目的路径别名配置在哪里？**  
答：路径别名配置在 `tsconfig.json` 文件中，配置了 `@/*` 映射到项目根目录。

**问：如何同时修复多个文件中的相对导入？**  
答：运行 `npm run lint:imports:fix` 命令，它会自动尝试修复检测到的相对导入路径。

**问：自动修复可能会导致哪些问题？**  
答：自动修复可能会错误地处理一些复杂的导入情况，特别是样式导入或第三方库的特殊导入。修复后应该进行测试，确保功能正常。
