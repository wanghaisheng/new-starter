# 类型安全落地 Checklist 提示词（对应第六章）

本文件为开发、评审、测试等场景下，针对 type-safety-strategy.md 第六章 Checklist 每一项实践，设计的具体提示词，便于 code review、自查、协作。

---

## 1. 始终以类型为契约驱动 adapter 设计
```md
- 新增 adapter/服务/接口时，是否先定义类型再实现逻辑？
- adapter 层输入输出类型与业务层是否完全一致？
- adapter 切换/组合时，类型定义是否保持不变？
```

## 2. 类型定义与 schema/接口文档同步演进
```md
- schema 或接口变更时，类型定义是否同步更新？
- 类型定义、数据库 schema、OpenAPI/接口文档三者是否一致？
- 是否有自动化工具定期比对 schema 与类型定义？
```

## 3. 通用类型、枚举、状态等统一在 common.ts 管理
```md
- 通用枚举、状态、平台等类型是否全部在 common.ts 定义？
- 业务类型、adapter、配置层是否全部 import 复用 common.ts 类型？
- 新增/调整通用类型时，是否同步全局替换引用？
```

## 4. CI/自动化校验 adapter 类型一致性
```md
- 新增/切换 adapter 是否已通过类型校验？
- 是否引入类型自动对齐脚本、类型生成工具、lint/CI 检查？
- 类型定义变更是否强制 code review？
```

## 5. 类型驱动配置与 Feature Flag
```md
- 所有环境参数、feature flag、策略开关是否有类型定义？
- 配置对象/feature flag 变更是否自动类型校验？
- 配置变更是否同步更新配置文档并支持类型校验和变更审计？
```

## 6. 多端/多适配协同的类型安全保障
```md
- 各端 adapter 层是否全部以统一类型为契约？
- 多端 adapter 是否用类型工厂自动注册和校验？
```

## 7. 类型驱动的自动化测试与 Mock
```md
- 接口、adapter、配置的类型定义能否自动生成 mock 数据/用例/文档？
- 前后端并行开发时，是否用类型生成 mock 服务？
```

## 8. 类型安全的可观测性与监控
```md
- 日志、埋点、监控等数据结构是否用类型定义？
- 类型定义变更是否自动同步监控/埋点平台？
```

## 9. 类型安全的数据迁移与版本演化
```md
- schema/type 变更是否用类型 diff 工具自动生成迁移脚本或兼容层？
- 是否支持多版本接口/数据并存，便于灰度、A/B 实验、老用户兼容？
```

---

> 建议将本提示词与 code-review、testing 等流程结合，作为类型安全最佳实践的自查与评审标准。
