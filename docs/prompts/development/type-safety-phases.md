# 类型安全分阶段落地提示词（配合第八章节）

本文件为开发、评审、测试等场景下，针对 type-safety-strategy.md 第八章节每一阶段的目标和实践，设计的具体提示词，可用于 code review、需求澄清、测试用例设计、mock 数据生成等环节。

---

## 0-1 阶段（快速原型/需求验证）

### 目标提示词
```md
- 本需求/功能的领域对象和核心流程，是否已用类型定义清晰表达？
- 当前接口/数据结构是否已通过类型定义自动生成 mock？
- adapter 层是否统一类型接口，便于 mock/本地/远程/多端切换？
- 是否已用类型驱动的自动化测试覆盖核心业务链路？
```

### 实践提示词
```md
- “请先补充/完善本功能的类型定义，再进行逻辑开发。”
- “该接口/数据结构能否自动生成 mock 数据并支持前后端并行联调？”
- “adapter 切换/组合是否做到类型契约不变？”
- “核心流程的自动化测试是否基于类型定义生成？”
```

---

## 1-10 阶段（团队扩展/多端协同/初步规模化）

### 目标提示词
```md
- 多端/多 adapter 是否全部以统一类型为契约？
- 通用类型、枚举、状态等是否全部收敛到 common.ts？
- 类型定义、schema、接口文档是否保持同步？
- 配置/feature flag 是否类型化并支持动态切换？
```

### 实践提示词
```md
- “请确保所有 adapter/多端实现严格遵循统一类型接口。”
- “通用枚举/状态类型是否已在 common.ts 定义并全局复用？”
- “类型定义变更是否已同步更新 schema/接口文档？”
- “配置和 feature flag 变更是否已类型校验和文档同步？”
- “mock/接口文档是否可由类型定义自动生成？”
```

---

## 10-100 阶段（大规模演进/弹性扩展/自动化治理）

### 目标提示词
```md
- schema/type 变更是否已自动生成数据迁移脚本？
- 日志、埋点、监控等数据结构是否类型化并与业务数据一致？
- CI/lint 是否已自动校验 adapter 类型一致性？
- 类型定义是否驱动监控、告警、数据分析等自动化工具链？
- 领域建模与类型定义是否持续演进、支持创新？
```

### 实践提示词
```md
- “schema/type 变更请同步生成/审查迁移脚本和兼容层。”
- “日志、埋点、监控等是否已统一类型定义，保证数据口径一致？”
- “CI/lint 是否能自动发现 adapter 类型不一致问题？”
- “监控、告警、分析等工具链是否已集成类型定义？”
- “领域模型和类型契约是否定期回顾并随产品演进？”
```
