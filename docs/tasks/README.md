- [ ] 完善迁移文档与目录说明
  - [ ] 按照 services-update/README.md 持续同步更新分层说明和迁移进度

#### 数据服务迁移与整合详细计划

1. **接口与类型定义迁移**
   - 将 `src/core/lib/db/interfaces.ts`、`types.ts` 迁移到 `src/core/services-update/data/interfaces.ts` 或 `types.ts`，合并重复内容，统一所有业务层调用的数据服务接口（如 `IDataService`）。
2. **工厂与服务实现迁移**
   - 将 `src/core/lib/db/factory.ts`、`service.ts` 迁移到 `src/core/services-update/data/factory/factory.ts`、`service.ts`。
   - 工厂负责实例化业务数据服务（如 Firebase、Mock、SQLite 等）。
   - 服务实现只保留底层能力，业务适配通过 adapter 实现。
3. **底层 clients 复用**
   - `lib/db/clients` 下的所有底层数据库客户端不迁移，adapter/service/factory 通过 import 使用。
   - adapter 只做“协议适配”，不做底层实现。
4. **兼容壳导出与逐步替换**
   - lib/db 下原文件全部变为兼容壳，export 新文件内容，并加迁移提示。
   - 逐步替换所有 import 路径为新结构，迁移完成后删除旧文件。
5. **文档与进度同步**
   - 在 docs/tasks/README.md 和 services-update/README.md 持续记录迁移进度和结构变更说明。

> 迁移完成后，lib/db 只保留 clients、schema、repository 等底层能力，所有高层接口、工厂、服务实现都迁移到新目录，adapter 只做适配，最终实现严格分层和唯一接口。
