# 配置服务与环境变量标准化专项任务

> 任务目标：根据 `src/core/services/infrastructure/config/README.md`，系统梳理并标准化配置服务的环境变量管理、配置注入与代码集成方式，提升多环境一致性和可维护性。

---

## 一、任务背景

- 现有配置服务支持多环境注入，但部分变量命名、注入方式、文档说明尚未完全标准化。
- 随着 mock/本地/生产等多环境切换需求增多，需统一变量命名、配置入口和服务集成方式。

---

## 二、核心任务清单

### 1. 变量命名与用途标准化
- [x] 梳理 config 层依赖的所有环境变量，统一命名风格（全大写+下划线，前缀体现作用域，如 `NEXT_PUBLIC_`、`API_`、`MOCK_`）。
- [x] 每个变量补充用途说明、典型取值、配置示例。
- [x] 变量用途与配置服务功能建立映射表。

### 2. 配置服务注入与读取方式统一
- [x] 配置服务统一通过 `.env` 文件或环境变量工具（如 dotenv、cross-env）注入变量。
- [x] 支持多环境配置文件（如 `.env.mock`、`.env.prod`），并在 config 服务内自动识别。
- [x] 变量读取逻辑集中在 config 服务，业务层/其它服务只能通过 config 服务获取配置。
- [x] 明确变量默认值、优先级与覆盖规则。

### 3. 文档与代码注释完善
- [x] `src/core/services/infrastructure/config/README.md` 中补充所有变量说明、配置示例、最佳实践。
- [x] 相关服务代码注释需引用本任务文档，便于团队查阅。
- [x] 变量变更需同步更新文档和配置示例。

### 4. 变量声明与类型安全
- [x] 在 config 服务中集中声明所有变量及类型，避免魔法字符串和隐式依赖。
- [x] 支持类型推断、自动补全，提升开发体验。

### 5. 验收标准
- [x] 变量命名、用途、注入、读取、文档全部标准化。
- [x] 业务层/其它服务均通过 config 服务获取配置，禁止直接读取 process.env。
- [x] 新增/变更变量流程规范，文档与代码同步。
