# hooks 统一优化任务清单

## 一、目标与背景

为进一步提升项目的可维护性、开发效率和用户体验，需对现有 hooks 体系进行统一优化，规范异常处理、用户提示、服务注入和文档示例等，确保所有业务数据流和用户交互体验一致。

---

## 二、优化任务清单

### 1. 统一异常处理与用户提示
- [ ] 所有业务 hooks 内部异常处理时，调用统一的 triggerToast/setToastMessage，自动弹出用户友好提示。
- [ ] 完善 useToast，支持多类型（success/error/warning/info）消息，便于不同场景提示。
- [ ] 新增全局 Toast/Snackbar 组件，确保所有页面/组件都能渲染统一风格的提示。
- [ ] hooks 返回值 error 字段继续细化类型，便于页面精准渲染和兜底。

### 2. 服务实例获取规范
- [x] 所有 hooks 均通过 Registry 获取服务实例，禁止 Factory 直连。
- [ ] 新增/修改 hooks 必须遵循此规范，代码评审需强制校验。

### 3. 状态输出与组合扩展
- [x] hooks 返回值统一包含 loading、error、empty 字段，命名风格一致。
- [ ] 支持 hooks 组合扩展（如 useUser + useAuth），异常处理逻辑可复用。

### 4. Mock/测试环境降级
- [x] Mock/测试环境下 hooks 自动降级到 mock service，保证测试可用性。
- [ ] 持续完善 hooks 自动降级和测试用例覆盖。

### 5. 文档与最佳实践
- [ ] 完善 hooks/README.md，补充典型用法、异常处理、用户提示等最佳实践。
- [ ] 每次 hooks 体系升级/优化需同步更新文档和示例代码。

---

## 三、建议实施步骤
1. 新增 Toast/Snackbar 组件，完善 useToast 支持多类型消息。
2. 所有业务 hooks 内部异常处理时调用 triggerToast，统一用户提示。
3. 持续补充 hooks/README.md 和测试用例，确保文档与实现同步。
4. 定期代码审查，确保 hooks 体系规范落地。

---

## 四、预期收益
- 异常处理和用户提示体验一致，减少重复代码和遗漏。
- 新增/修改 hooks 规范化，团队协作效率提升。
- 便于后续扩展多语言、A/B 测试、个性化提示等能力。

---
